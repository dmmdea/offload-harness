# Composite Tier (0.116.0) Implementation Plan — v2 (after the council)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Qube one installed tier (`blackwell-3x16`) that *composes* `blackwell-16` and `blackwell-2x16` as device layers, decide per task which layer and seat serve it, record that decision truthfully on every result, advertise the layers to the fleet, and ship it as 0.116.0 with live gates on the Qube that can fail.

**Architecture:** The tier table (`setup/templates/profiles.json`) declares `composes` + `layers`; `tierseed` seeds `tier_profile`, `tiers` and `layers` into `config.json`, so at runtime everything reads config (a box that seeds none has one implicit layer and is byte-identical on every result, health, status and ledger surface). ONE pure package `internal/placement` turns (task class, token need, quality gate, `context_class`, budget, live occupancy, live guards) into a `Decision` — used identically for the local box, for a remote node's advertised layers (the delegator builds the same inputs from health rows), and by the node itself at admission (guards are re-run where the card is). Guards for the display card (free VRAM minus the seat's own footprint on that card ≥ floor, free host RAM ≥ the seat's need, operator away by console-session lock state / last input / shell notification state) read the machine live and fail CLOSED. A leaf package `internal/gpuprobe` owns the nvidia-smi and host-RAM readers.

**Tech Stack:** Go 1.26 (stdlib + `golang.org/x/sys/windows` already in go.mod), llama-swap YAML templates, PowerShell installer, Markdown docs generated by `cmd/gentiers`.

**Spec:** `docs/superpowers/specs/2026-09-09-qube-composite-tier-design.md` (APPROVED 2026-09-09). Read it first.

## What the council changed (2026-09-09 20:4x — five personas, verdict RESHAPE; all recorded in ADR 0039, Task 12)

R1. **Window overflow escalates to the PAIR layer's long seat** (`qwen3.8-27b-262k`, 262,144 window, prefill 1,197 t/s on the 5060 Ti pair — gates NOTES 2026-09-01 G3) and **only when the pair's agent seat is idle or cold**; otherwise the contract WAITS (the capacity wait credits the idle time) and `placed.reason` names the eviction it would cause. The **triple** layer's `qwen3.8-flash-next-262k` (prefill 69 t/s: a 200k prompt ≈ 48 min against a 900 s cap) is entered on an explicit `context_class: "long"` only, under a feasibility check (tokens ÷ prefill t/s ≤ the contract's budget) and the guards. Spec D2/D4 said "triple on window overflow"; it cannot finish inside any contract budget, measured.
R2. **D3's saturation rule is RECORDED, never ACTED on.** The live matrix (`interactive: "+residents & (q38 | q38x | q38v | … | g26a | g12 | ge4 | ge2 | qvl)"`) makes every single-card seat mutually exclusive with the pair seat, and the pair seat pins its KV pool from all free memory minus 0.5 GiB, so "overflow to the single layer" can never fire on this box, and treating saturation as "local busy" would hand quality-gated contracts to the Lenovo 4B (the exact trade D3 forbids) and defer best-effort ones after 120 s where today they queue in vLLM and complete. So: a saturated pair is written into `placed.reason` ("pair at 32/32 in flight — queued in the seat"), nothing is re-placed, nothing waits. The single-layer overflow branch is NOT built.
R3. **Seat roles live inside layers**, every seat carries its own device PIN (`device`), and the pair's agent seat is derived from `vllm_seat` at seed time (no duplicated numbers). `placed.devices` is the seat's pin, never the layer's alternatives list.
R4. **The block is published as `placed`**; `placement` (the reason string) is untouched — `integrations/opencode/src/plugin.ts:347-354` and `fleet_smoke_cmd.go` read it as a string.
R5. **ONE placement rule.** Remote nodes advertise their layers (spec + live state) in health; the delegator runs the same `Decide` over them; the dispatched contract carries `layer`; the node re-runs `Decide` for that layer with its OWN live readers so the display-card guards are evaluated where the card is. No second "fit" heuristic across layers.
R6. **Guards fixed and fail-closed:** floor = `free(display card) − seat.display_footprint_gib ≥ floor` (the old check admitted a 10.5 GB load onto a card with 9 GB free); a `host_ram` guard for seats that hold tens of GB of experts in RAM; presence = console-session LOCKED ⇒ away, else last-input idle ≥ threshold AND the shell not in a busy/fullscreen/presentation state ⇒ away; any probe failure ⇒ refuse; **`operator_presence` defaults to `present`** (the display card fails closed until the operator sets `auto` or `away`). Devices are matched by index OR UUID; the Qube's live config pins the display card by UUID because the board reorders on power loss.
R7. **A dormant, guarded `display` layer for the small cascade rungs** (e2b 2.6 GB / e4b 6.2 GB fit under the 4 GiB floor beside a busy pair — the only idle VRAM on the box) ships declared with `dormant: true`: template twins pinned to device 1, a concurrent matrix set beside the vLLM seat, one decision row, and the cascade's rung substitution. It is MEASURED once in Task 13 while the operator is away (desktop floor held? summarize wall vs. waiting behind the pair?) and the number goes to the operator; enabling it is one config edit (`dormant: false`) that only the operator makes. If the measurement says no, the layer is deleted before the PR merges.
R8. **Scope cut:** fleet-overview layer cards, `top` sub-rows and the ledger `by_layer` summary are HELD until placement makes a card show something different (ADR "not in this record"); the ledger keeps a `layer` column so the figure can be summed later.

```go
type LayerSeat struct {
	Role                string            `json:"role"`                            // router | agent | long | ocr | vision | stt
	Model               string            `json:"model,omitempty"`                 // llama-swap id or alias; "" for router
	Device              string            `json:"device"`                          // this seat's CUDA_VISIBLE_DEVICES pin: "0" | "2" | "0,2" | "0,1,2" | "1"
	CtxTokens           int               `json:"ctx_tokens,omitempty"`
	MaxInflight         int               `json:"max_inflight,omitempty"`          // vLLM max_num_seqs; 0 = never saturated by count
	FootprintGiB        float64           `json:"footprint_gib,omitempty"`         // VRAM on each device of Device, measured alone
	DisplayFootprintGiB float64           `json:"display_footprint_gib,omitempty"` // VRAM this seat puts on the layer's display device
	HostRAMGiB          float64           `json:"host_ram_gib,omitempty"`          // host RAM held while loaded (experts on CPU)
	PrefillTPS          float64           `json:"prefill_tps,omitempty"`           // measured prompt-processing rate, for the feasibility check
	ModelMap            map[string]string `json:"model_map,omitempty"`             // router role only: route key (workhorse|triage) → twin model on this layer
}

type LayerSpec struct {
	Name            string      `json:"name"`             // single | pair | triple | display
	Tier            string      `json:"tier"`
	Devices         []string    `json:"devices"`          // the device SETS this layer may occupy (documentary; seats carry the pin)
	Seats           []LayerSeat `json:"seats"`
	OptIn           bool        `json:"opt_in,omitempty"`
	Dormant         bool        `json:"dormant,omitempty"`        // declared, never placed until the operator flips it
	DisplayDevice   string      `json:"display_device,omitempty"` // index or GPU-UUID
	DisplayFloorGiB float64     `json:"display_floor_gib,omitempty"`
	Guards          []string    `json:"guards,omitempty"` // display_floor | presence | host_ram
}
```
