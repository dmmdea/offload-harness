### Fixed - a bad comfy_instance setup, a broken config file or a relative path no longer lets a ComfyUI run fall back to the default instance or split the lease

- **What was wrong.** A `comfy_instance` that failed its own checks (a leftover `comfy_cuda_device`, port 8188, a bad name), or one set only inside a family overlay, made the harness drop the instance, so the render runner drove the default ComfyUI on port 8188, which on a shared box is the owner's. The ComfyUI CLI verbs also ran on built-in defaults when the config file could not be parsed or the named file did not exist, with only a warning. A relative `pipelines[].workdir` was accepted and resolved against whatever directory the node was started in, and a relative `state_dir` or `gpu_lock_path` gave each working directory its own lease, so a reserved card was rendered on anyway.
- **What it does now.** An invalid named instance keeps its name and gets an endpoint that is never 8188, so the runner refuses the render and the post-run free never touches 8188. A family overlay with a bad instance pair is refused by name at load and when the family is picked. `generate-image` (and `--batch`), `inpaint-image`, `upscale-image`, `run-graph`, `edit-image-generative`, `generate-video`, `animate-character` and `generate-audio` refuse when a config file was named or found but could not be parsed or validated, or when `--config` or `$LOCAL_OFFLOAD_CONFIG` names a missing file; with no config file at all they behave as before. A relative `workdir`, `state_dir` or `gpu_lock_path` is refused by name at load. The environment forms of the lease root are not checked.
- **Checks.** `go build -p 2 ./...`, `go vet -p 2` on the touched packages and `go run ./cmd/changelog check`; the ComfyUI verbs run once against a config with a trailing comma and against a missing `--config` path.
