### Added - `tools_schema_profile = "compact"`: the advertised MCP tool list with every tool and parameter kept and the prose cut to a reviewed per-tool keep-list

- **The defect.** A client that sends every MCP tool schema on every call (opencode has no deferred tool search) pays the whole advertised list as prompt tokens on every turn, and the list had grown: re-measured at this build with the Qwen3.8 tokenizer (vocab-only, no weights, no GPU), the 31 tools of a delegation-enabled box are 30,537 tokens in the seat's chat-template rendering, against the 20,868 tokens (35 tools) recorded at 0.137.0, and the plugin's twelve `recon` tools are 11,867 against 8,265. Both old figures no longer hold.
- **The change.** A new config key `tools_schema_profile`: `"full"` (the default, and what an unset key means) advertises every description as written; `"compact"` advertises the same tools with the prose cut. `"compact"` keeps every tool, in order, and every parameter name, `type`, `enum`, `items`, `required` entry and numeric bound at every depth, so a call valid against the full list is valid against the compact one. It cuts each description (a tool's and each parameter's) to its first sentence, grown to the next sentence when the first is under 28 characters and shortened at a clause boundary when it runs past 320 characters (tool) or 200 (parameter) and the dropped part carries no constraint word, plus the sentences a reviewed per-tool keep-list names, verbatim and in the order the description has them. It drops `examples`, `example`, `title` and `$comment`. A value other than `full` or `compact` fails the config load by name; a hand-built `Config` with one reads as `full`.
- **Where it is wired.** `internal/mcpserver/toolsprofile.go`: a receiving middleware on `tools/list`, installed only when the profile is compact; the keep-list is `internal/mcpserver/toolsprofile_keep.go`. The result's tools alias the registry, so each is copied before it is changed; the registered schema, the handlers and the call-time checks are untouched, and anything the rewrite cannot parse stays as it was (the failure mode is a full schema, never a broken one). Schemas are rewritten with an order-preserving JSON walk, so parameters keep their order. `config.example.json` is regenerated (`go run ./cmd/genexample`), and `docs/OPERATOR-GUIDE.md` has the key's row.
- **The default is byte-identical.** The `tools/list` result of the shipped default, of `"full"` and of an unset key is the same bytes as the 0.186.0 base advertises: SHA-256 `e4840d2c3a9e879d...` on both trees, captured on the server's side of an in-memory transport with the new `TestToolsListDump` helper (`cmp` exit 0), and the same hash again from the final tree of this change. With no middleware installed for the default, that holds by construction; `TestDefaultProfileIsFull` pins that an unset key, `"full"` and `Default()` agree and that compact differs.
- **What compact keeps is a reviewed list, not a word rule.** The first version kept every later sentence that held one of a closed list of safety words. A review of the live descriptions showed it wrong in both directions: a mutation sweep removed each of its 18 words in turn and 15 left every compact test green, it dropped sentences a caller relies on (the only cloud tool and its opt-in rule; the video generator's "pass `model` ONLY to override that deliberately" and "set `fast=true` ONLY when the caller explicitly wants a draft"; the write door's caps and grants; the "if it can't ... it returns `deferred:true` and you should do it yourself" sentence of five lanes; "an EMPTY findings list ... is not a verification"), it kept a "Non-zero means a node is broken" sentence cut loose from the `summary.infrastructure` sentence it is about, and it kept by accident 49 distinct sentences that are result shapes or queue mechanics. Now each description keeps its opening sentence and exactly the sentences `toolsprofile_keep.go` names for that tool (74 entries, each with its reason and the sentences it cannot be read without); everything else is dropped.
- **The gate.** `TestEveryConstraintSentenceIsKeptOrDroppedWithReason` reads the live full descriptions of every tool and parameter, exactly as `tools/list` emits them, on eight surfaces: the delegation pair and the browse lane on, with the three accelerators together as local devices (the 45-tool surface), the same three together as fleet accelerators, and each of the three alone, once as a local device and once as a fleet accelerator. It fails for every sentence that carries a trigger word and is neither in the compact description of that tool and parameter nor on the reviewed dropped-with-reason list (`toolsprofile_dropped_test.go`, 107 entries: tools, exact sentence, reason). The trigger words are the constraint words (`never`, `refuse*`, `only`, `must`, `not`, any `n't` contraction, `cannot`, `required`, `without`, `opt-in`, `no delete|shell|run|network|cloud|write`, and the words the first list used) and the words that say the caller's data leaves the box (`forward*`, `travel*`, `fleet node`, `tailnet`, `sent`, `cloud`). A rule added to a description later turns it red until it is classified, and a reworded one turns it red again, because every entry is the exact sentence. It checks the compact output, so a keep entry that does not match what the splitter produces is caught. It cannot see a rule written without any of those words; the keep-list can name such a sentence (it does for the write door's "neither says the change is CORRECT, so read the diff"), but nothing forces it to.
- **Why eight surfaces, and the data-leaves-the-box words.** The first gate read two surfaces and both list the three accelerators together, so the shared-name rule gave each tool name to one device: the Coral's and the RKNPU's `offload_image_embed` descriptions ("space=efficientnet-edgetpu-s - NOT a CLIP space" and "vectors from different devices are never comparable") are advertised on a box that lists only that device and were read by no test; both are now kept, as the siglip2 pairing sentence already was. The first gate also classified a sentence only if it held a prohibition word, and the fleet-accelerator note that `registerAccelTools` appends (the call is forwarded to another node and the image bytes travel with the job) holds none: compact dropped it from all 13 forwarders of the fleet surface (18 tool and device pairs over the three devices) while the kept opening sentence still said "on the LOCAL ... NPU (free, on-box ...)". The note is now kept, one entry per device. The new words found more sentences of the same kind, and each was read: the vision tools' `route` parameter ("the image is read on THIS box and travels with the job": `offload_assess_image`, `offload_ocr`, `offload_vqa`), transcribe's route sentence (the default route sends the audio to a fleet node when this box's whisper is held) and browse's (the visible page text goes to a decision endpoint that may front a cloud model) are kept; five are dropped with a reason (the vision tools' tool-level route sentence and transcribe's parameter-level one, both restated by a kept sentence; the research lane's "cloud research subagent" pointer; the run_graph ticket's copy of what was sent). The lead guard has the same words, so the clause-boundary cut no longer drops "the input files you name travel to it" from the `route` parameter of the three generators, `offload_animate_character` and `offload_run_graph`.
- **A route sentence the gate could not see.** `offload_compose_video`'s tool-level route sentence says the render runs on a fleet node when this machine has no composition lane and that an inline composition or a project directory goes there as a project bundle; it holds no prohibition word and none of the first data-leaves-the-box words, so the gate skipped it and compact dropped it with no entry on either list. `fleet node` (and `fleet nodes`) is now a trigger word of the gate and of the lead guard, and the sentence is kept. The wider vocabulary newly caught four sentences, each read: this one (kept), transcribe's parameter-level route sentence (dropped: the kept tool-level route sentence says the audio goes to a fleet node by default and how to pin it), the `pin_reason` sentence about a remote pin's retry staying on a fleet node (dropped: placement mechanics, on `agent_delegate` and `offload_research`), and `agent_delegate`'s `results[].node` sentence (dropped: result reading). Only the compose-video tool changes in the compact list (80 tokens).
- **Measured (31 tools, 0.186.0 plus this change; llama.cpp b11146 `llama-tokenize`, vocab-only, over the Qwen3.8-27B GGUF).** Chat-template rendering (`<tools>`, one `{"type": "function", "function": {...}}` per line): every advertised tool 30,537 full and 17,280 compact (13,257 saved, 43.4%); the twelve `recon` tools 11,867 and 6,682 (43.7%); the other nineteen 18,677 and 10,605 (43.2%); the four Tier-1 tools 1,232 and 847 (31.2%). On the largest surface, the same 31 plus the browse lane and the three accelerators (45 tools, measured, not estimated): 33,532 and 19,644 (41.4%). The `tools/list` JSON the server writes: 28,469 and 15,214 (31 tools), 11,157 and 5,974 (`recon`). The same lists before the data-leaves-the-box words joined the gate measured 16,811, 6,626, 10,192 and 19,116 compact, so the new keep entries and the longer route parameters cost 469, 56, 413 and 528 tokens; the full columns did not move and the default list is byte-identical (SHA-256 `e4840d2c3a9e879d...`, checked again). With the three accelerators as fleet accelerators (45 tools, 13 forwarders) the lists measure 34,237 full and 20,352 compact; the note is kept, and the 13 notes together are 705 tokens of the full list. The earlier compact figures of this change (19,674 and 8,011), measured with the safety-word rule, are superseded.

- **Also.** The sentence splitter no longer cuts at an ellipsis: it cut the `waiter_token` collect sentence in two ("... only to collect the result" was dropped and the kept half ended mid-sentence). The independent structure comparison in the tests no longer strips a parameter that is called `title` or `example`, and the full-surface guard names the browse lane and one tool of each accelerator instead of a bare count.

### Fixed - the fleet-accelerator note of `offload_text_embed` named an argument the tool does not have

- On the fleet surface `offload_text_embed`'s forwarding note said `image_path is read HERE and its bytes travel with the job`, but the tool takes `text` (its required argument) and reads no image. The note is now built from the table row's own required argument (`fleetAccelNote`): an image tool keeps the sentence it had byte for byte, `offload_text_embed` says `text travels with the job`. `TestFleetAcceleratorNoteNamesTheToolsOwnArgument` pins it over all 18 forwarders (the row's required argument appears in the note, and no `*_path` argument the tool does not take is named). Compact keeps the new sentence under its own keep entry. The default `tools/list` is unchanged (SHA-256 `e4840d2c3a9e879d...`), the 31- and 45-tool lists too; only the fleet-accelerator variant changes (13 notes: 705 tokens, 13 fewer).
