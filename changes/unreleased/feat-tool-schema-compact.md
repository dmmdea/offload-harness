### Added - `tools_schema_profile = "compact"`: the advertised MCP tool list with every tool and parameter kept and the prose cut (ENH-13a)

- **The defect.** A client that sends every MCP tool schema on every call (opencode has no deferred tool search) pays the whole advertised list as prompt tokens on every turn, and the list had grown: re-measured at this build with the Qwen3.8 tokenizer (vocab-only, no weights, no GPU), the 31 tools of a delegation-enabled box are 30,537 tokens in the seat's chat-template rendering, against the 20,868 tokens (35 tools) recorded at 0.137.0, and the plugin's twelve `recon` tools are 11,867 against 8,265. Both old figures no longer hold.
- **The change.** A new config key `tools_schema_profile`: `"full"` (the default, and what an unset key means) advertises every description as written; `"compact"` advertises the same tools with the prose cut. `"compact"` keeps every tool, in order, and every parameter name, `type`, `enum`, `items`, `required` entry and numeric bound at every depth, so a call valid against the full list is valid against the compact one. It cuts each description (a tool's and each parameter's) to its first sentence, grown to the next sentence when the first is under 28 characters and shortened at a clause boundary when it runs past 320 characters (tool) or 200 (parameter) and the dropped part carries no safety word, and keeps every later sentence that carries a safety word (`never`, `do not`, `may not`, `must`, `cannot`, `refuse`, `denied`, `read-only`, `trusted`, `untrusted`, `unattended`, `sandbox`, `safety`, `advisory`, `forbidden`, `irreversible`, `destructive`), whole. It drops `examples`, `example`, `title` and `$comment`. A value other than `full` or `compact` fails the config load by name; a hand-built `Config` with one reads as `full`.
- **Where it is wired.** `internal/mcpserver/toolsprofile.go`: a receiving middleware on `tools/list`, installed only when the profile is compact. The result's tools alias the registry, so each is copied before it is changed; the registered schema, the handlers and the call-time checks are untouched, and anything the rewrite cannot parse stays as it was (the failure mode is a full schema, never a broken one). Schemas are rewritten with an order-preserving JSON walk, so parameters keep their order. `config.example.json` is regenerated (`go run ./cmd/genexample`), and `docs/OPERATOR-GUIDE.md` has the key's row.
- **The default is byte-identical.** The `tools/list` result of the shipped default, of `"full"` and of an unset key is the same bytes as the 0.186.0 base advertises: SHA-256 `e4840d2c3a9e879d...` on both trees, captured on the server's side of an in-memory transport with the new `TestToolsListDump` helper (`cmp` exit 0). With no middleware installed for the default, that holds by construction; `TestDefaultProfileIsFull` pins that an unset key, `"full"` and `Default()` agree and that compact differs.
- **Measured (31 tools, 0.186.0 plus this change; llama.cpp b11146 `llama-tokenize`, vocab-only, over the Qwen3.8-27B GGUF).** Chat-template rendering (`<tools>`, one `{"type": "function", "function": {...}}` per line): every advertised tool 30,537 full and 19,674 compact (10,863 saved, 35.6%); the twelve `recon` tools 11,867 and 8,011 (32.5%); the other nineteen 18,677 and 11,670 (37.5%); the four Tier-1 tools 1,232 and 824 (33.1%). The `tools/list` JSON the server writes: 28,469 and 17,610 (all), 11,157 and 7,303 (`recon`). The compact list is below both 0.137.0 figures (19,674 under 20,868; 8,011 under 8,265), though the tool counts differ (31 against 35, the set is per-box). The table, the method and the re-measure command are in `docs/systems/opencode-integration.md` (Tool schema size).
- **The safety-word decision, measured.** `only` is not a safety word: it is plain description in a large share of the prose, and keeping every sentence that holds it costs 1,801 tokens (19,674 become 21,475, `recon` 8,011 becomes 8,872), above both old figures. A real "only" prohibition is caught by its companion word (`TRUSTED CODE ONLY ... never pass third-party pages`, `ADVISORY ONLY: this lane never gates a merge`). `refuse`, `may not` and `denied` are on the list and cost 908 tokens over the same list without them (18,766 against 19,674; the `recon` set 7,530 against 8,011): they carry, among others, the privacy sentence of `pin_reason` ("the material may not leave this box").
- **Tests.** `TestCompactKeepsEveryToolAndParameter` (same tools in the same order; each input schema equals the full one minus prose, compared by a naive independent strip, over a config with the delegation pair, the browse lane and all three accelerators on), `TestCompactRequiredParametersSurvive`, `TestCompactNeverLosesASafetyWord` (the count of safety words in every tool's descriptions is the same under both profiles), `TestCompactKeepsNamedSafetySentences` (nine named sentences including the compose-video `TRUSTED CODE ONLY` one, the review-diff `ADVISORY ONLY` one, `agent_run`'s `READ-ONLY` one and `write_root`'s `the harness never applies it`, each looked up in the full description first so a rewording fails loudly), `TestDefaultProfileIsFull`, `TestCompactDoesNotTouchTheRegistry`, `TestCompactProfileLeavesCallsAlone` (a bad call is answered identically under both profiles), the sentence splitter and cut tables, a property named `description` that must not be mistaken for the keyword, an unparseable schema that must come back unchanged, and the config tests for the default, the closed set and the refusal by name.
- **Mutations.** Six one-line mutants, each restored byte for byte (`git diff --quiet` exit 0) and each red: dropping `never` from the word list (`TestCompactKeepsNamedSafetySentences`, `TestCompactDescription`), compacting no schema (the `write_root` pin), dropping `required` from the walk, dropping `enum` from the walk (`TestCompactKeepsEveryToolAndParameter`, `TestCompactRequiredParametersSurvive`, the property-named-description case), cutting a lead without the safety check on the dropped tail (`TestCompactNeverLosesASafetyWord`, `TestCompactDescription`), and installing the middleware for every profile (`TestDefaultProfileIsFull`).
