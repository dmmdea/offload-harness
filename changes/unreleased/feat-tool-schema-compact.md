### Added - `tools_schema_profile = "compact"`: the advertised MCP tool list with every tool and parameter kept and the prose cut to a reviewed per-tool keep-list

- **The defect.** A client that sends every MCP tool schema on every call (opencode has no deferred tool search) pays the whole advertised list as prompt tokens on every turn, and the list had grown: re-measured at this build with the Qwen3.8 tokenizer (vocab-only, no weights, no GPU), the 31 tools of a delegation-enabled box are 30,537 tokens in the seat's chat-template rendering, against the 20,868 tokens (35 tools) recorded at 0.137.0, and the plugin's twelve `recon` tools are 11,867 against 8,265. Both old figures no longer hold.
- **The change.** A new config key `tools_schema_profile`: `"full"` (the default, and what an unset key means) advertises every description as written; `"compact"` advertises the same tools with the prose cut. `"compact"` keeps every tool, in order, and every parameter name, `type`, `enum`, `items`, `required` entry and numeric bound at every depth, so a call valid against the full list is valid against the compact one. It cuts each description (a tool's and each parameter's) to its first sentence, grown to the next sentence when the first is under 28 characters and shortened at a clause boundary when it runs past 320 characters (tool) or 200 (parameter) and the dropped part carries no constraint word, plus the sentences a reviewed per-tool keep-list names, verbatim and in the order the description has them. It drops `examples`, `example`, `title` and `$comment`. A value other than `full` or `compact` fails the config load by name; a hand-built `Config` with one reads as `full`.
- **Where it is wired.** `internal/mcpserver/toolsprofile.go`: a receiving middleware on `tools/list`, installed only when the profile is compact; the keep-list is `internal/mcpserver/toolsprofile_keep.go`. The result's tools alias the registry, so each is copied before it is changed; the registered schema, the handlers and the call-time checks are untouched, and anything the rewrite cannot parse stays as it was (the failure mode is a full schema, never a broken one). Schemas are rewritten with an order-preserving JSON walk, so parameters keep their order. `config.example.json` is regenerated (`go run ./cmd/genexample`), and `docs/OPERATOR-GUIDE.md` has the key's row.
- **The default is byte-identical.** The `tools/list` result of the shipped default, of `"full"` and of an unset key is the same bytes as the 0.186.0 base advertises: SHA-256 `e4840d2c3a9e879d...` on both trees, captured on the server's side of an in-memory transport with the new `TestToolsListDump` helper (`cmp` exit 0), and the same hash again from the final tree of this change. With no middleware installed for the default, that holds by construction; `TestDefaultProfileIsFull` pins that an unset key, `"full"` and `Default()` agree and that compact differs.
- **What compact keeps is a reviewed list, not a word rule.** The first version kept every later sentence that held one of a closed list of safety words. A review of the live descriptions showed it wrong in both directions: a mutation sweep removed each of its 18 words in turn and 15 left every compact test green, it dropped sentences a caller relies on (the only cloud tool and its opt-in rule; the video generator's "pass `model` ONLY to override that deliberately" and "set `fast=true` ONLY when the caller explicitly wants a draft"; the write door's caps and grants; the "if it can't ... it returns `deferred:true` and you should do it yourself" sentence of five lanes; "an EMPTY findings list ... is not a verification"), it kept a "Non-zero means a node is broken" sentence cut loose from the `summary.infrastructure` sentence it is about, and it kept by accident 49 distinct sentences that are result shapes or queue mechanics. Now each description keeps its opening sentence and exactly the sentences `toolsprofile_keep.go` names for that tool (64 entries, each with its reason and the sentences it cannot be read without); everything else is dropped.
- **The gate.** `TestEveryConstraintSentenceIsKeptOrDroppedWithReason` reads the live full descriptions of every tool and parameter (the 45-tool surface with the delegation pair, the browse lane and all three accelerators on, and the fleet-accelerator variant), and fails for every sentence that carries a constraint word (`never`, `refuse*`, `only`, `must`, `not`, any `n't` contraction, `cannot`, `required`, `without`, `opt-in`, `no delete|shell|run|network|cloud|write`, and the words the first list used) that is neither in the compact description of that tool and parameter nor on the reviewed dropped-with-reason list (`toolsprofile_dropped_test.go`, 99 entries: tools, exact sentence, reason). A rule added to a description later turns it red until it is classified, and a reworded one turns it red again, because every entry is the exact sentence. It checks the compact output, so a keep entry that does not match what the splitter produces is caught. It cannot see a rule written without any of those words; the keep-list can name such a sentence (it does for the write door's "neither says the change is CORRECT, so read the diff"), but nothing forces it to.
- **Measured (31 tools, 0.186.0 plus this change; llama.cpp b11146 `llama-tokenize`, vocab-only, over the Qwen3.8-27B GGUF).** Chat-template rendering (`<tools>`, one `{"type": "function", "function": {...}}` per line): every advertised tool 30,537 full and 16,811 compact (13,726 saved, 44.9%); the twelve `recon` tools 11,867 and 6,626 (44.2%); the other nineteen 18,677 and 10,192 (45.4%); the four Tier-1 tools 1,232 and 847 (31.2%). On the largest surface, the same 31 plus the browse lane and the three accelerators (45 tools, measured, not estimated): 33,532 and 19,116 (43.0%). The `tools/list` JSON the server writes: 28,469 and 14,745 (31 tools), 11,157 and 5,918 (`recon`). The earlier compact figures of this change (19,674 and 8,011), measured with the safety-word rule, are superseded.
- **Against 0.137.0, like for like where possible.** The same twelve `recon` tools: 8,265 then, 11,867 now in full, 6,626 compact. All tools is not the same set (35 then, 31 now, because the set is per-box): 596 tokens per tool then, 985 per tool in full now, 542 compact; at 45 tools compact is 19,116, 425 per tool, still below 20,868. Per tool, where 0.137.0 recorded a figure (then in full; now in full and compact): `agent_delegate` 2,903; 4,173 and 2,684. `offload_status` 660; 1,074 and 238. `offload_compose_video` 991; 1,153 and 725. The four Tier-1 tools 847; 1,232 and 847. No other per-tool figure was recorded, so the rest cannot be compared one by one. The table, the method and the re-measure command are in `docs/systems/opencode-integration.md` (Tool schema size).
- **Also.** The sentence splitter no longer cuts at an ellipsis: it cut the `waiter_token` collect sentence in two ("... only to collect the result" was dropped and the kept half ended mid-sentence). The independent structure comparison in the tests no longer strips a parameter that is called `title` or `example`, and the full-surface guard names the browse lane and one tool of each accelerator instead of a bare count.
- **Tests.** The gate above and its companions: `TestGateFiresOnANewConstraintSentence` (a synthetic tool gaining a rule is reported until it is kept or dropped with a reason, and a reworded rule is reported again), `TestKeepListEntriesAreLive` and `TestDroppedEntriesAreLive` (every entry matches a live sentence outside an opening position), `TestKeepAndDroppedListsAreDisjoint`, `TestKeepListEntriesSurviveWhereverTheyAppear`, `TestLeadCutNeverDropsAConstraintWord`, `TestLeadGuardCoversTheGate`; `TestCompactKeepsNamedSafetySentences` and `TestCompactKeepsNamedParameterSentences` (the compose-video `TRUSTED CODE ONLY` sentence, the review-diff `ADVISORY ONLY` one, `agent_run`'s `READ-ONLY` one, the only-cloud-tool sentences, the video generator's `ONLY` rules, the write door's caps and grants, the five `deferred:true` sentences, `pin_reason`'s privacy and locality, the fleet-narrowing rule and the ticket collect sentence, each looked up in the full description first so a rewording fails loudly), `TestCompactKeepsTheReferentOfAKeptSentence`, `TestCompactKeepsEveryToolAndParameter` (same tools in the same order; each input schema equals the full one minus prose, compared by a naive independent strip, over the full surface), `TestCompactRequiredParametersSurvive`, `TestDefaultProfileIsFull`, `TestCompactDoesNotTouchTheRegistry`, `TestCompactProfileLeavesCallsAlone` (a bad call is answered identically under both profiles), the sentence splitter and cut tables, a property named `description`, `title` or `example` that must not be mistaken for the keyword, an unparseable schema that must come back unchanged, and the config tests for the default, the closed set and the refusal by name. Red first: the failing gate (about 190 unclassified sentences against an empty dropped list), the pins and the splitter case were committed before the keep-list that turns them green.
- **Mutations.** Nine one-line mutants against the new mechanism, each restored byte for byte (`git diff --quiet` exit 0) and each red: removing one keep entry (the only-cloud-tool sentence: `TestCompactKeepsNamedSafetySentences` and the gate), removing one dropped entry (the gate), adding a sentence with `never` to a tool description (the gate), dropping `never` from the lead guard and dropping `only` from it (`TestLeadGuardCoversTheGate`, the gate and `TestCompactDescription`), removing a referent from an entry (`TestCompactKeepsTheReferentOfAKeptSentence`), removing the ellipsis rule from the splitter (`TestSplitSentences` and five more), making the cut ignore the keep-set, and indexing the keep-set under the wrong tool name.
