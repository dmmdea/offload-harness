### Added - the qwen-image-2.1 edit takes the card-only two-card placement, and the multicard launch notes move from every command to `doctor`

- **What it does.** `--placement multicard` on `render/comfy-edit.mjs` now serves `--family qwen-image-2.1` (`render/multicard-recipes.json`, `render/multicard-recipes.mjs`, `render/wf-qwen-image-21.mjs`, `render/comfy-edit.mjs`, `internal/mediacap/multicard.go`, `internal/config/config.go`). Two rows, `qwen-image-2.1-edit/bf16` and `qwen-image-2.1-edit/int8_convrot`, take the loaders, resident shares and compute-first card order of the measured 2.1 image rows. The graph reads the conditioning through node 14, `OffloadFreeAfterEncode`, after the text encode (the vision tower and the reference VAE encode run inside it), so the 16.33 GiB text encoder leaves both cards before the DiT lands. `--cache-device` defaults to `gpu` under the placement and takes `gpu` or `off` only: `auto` and `cpu` can pin the prefix cache in host RAM, and the runner and the builder refuse them by name (a bound `gen_edit_cache_device` of `auto` or `cpu` on a multicard 2.1 edit binding is also warned of at load). The edit canvas is judged on the DiT sequence (the target counted twice plus every reference, each `--resolution` squared) against the rows' `maxPixels` of 4,194,304, and a refusal names the largest `--resolution` that fits. Both rows are `predicted` (Go `Measured: false`): no card-only edit has been rendered, so the peaks are ceilings and a first real render promotes them. The load-time recipe-family check (`editRecipeFamilies`) now includes the family, and `docs/systems/media-generation.md` has the rows and a paragraph on the edit specifics.
- **What it fixes.** After the media placements went multicard, every `local-offload` command (even `gpu status`) printed the same twelve `comfy_cuda_device` / `comfy_dynamic_vram` warning lines, and printed them more than once per process. Root cause: `warnImageGenBindingTraps` runs from `load` (`internal/config/config.go`) on every `config.Load`, and each consumer loads the config again (`gpu status` loads it five times through `loadCfg`), so every binding warning was said once per load; and `warnMulticardLaunchTo` repeated the flat-setting warning for the default binding and again for every named family that only inherits it. Now the binding-trap warnings are written once per process (a line already said is not said again), and the two informational notes are not warnings at all: `Config.MulticardLaunchNotes` names the multicard seats (default image and edit bindings and the families that resolve to multicard) once per setting, and `local-offload doctor` prints them as `multicard:  NOTE` rows (`main.go`). The real misconfiguration warnings (no recipe for the family, card-scoped leases off, pooled-seat traps) are unchanged.
- **Why.** The 2.1 edit was the one family that had a card-only image placement and no edit one, so it could not run on the two non-display cards without host RAM. The flat `comfy_cuda_device` and `comfy_dynamic_vram` still serve the single-card routes (inpaint, upscale, the single-pinned edit families), so a config that keeps them next to multicard seats is deliberate and warning of it on every command taught the operator to stop reading the warnings.
- **Check.** No GPU or ComfyUI work was done, so no edit has been rendered card-only. Real runs: `planEdit` on two real PNG headers (1024x1024 and 2048x2048) built the bf16, int8 convrot and Turbo edit graphs under the placement (loader classes, node 14 and the sampler's conditioning read through it, cache device `gpu`), refused `--cache-device auto`, refused four images at 1024 (5.24 MP against the 4.19 MP cap) and one 2048x2048 image at `--resolution 0`, and refused a 2.1 DiT file with no row. A built binary run with a copy of a config that binds multicard on the image seat, the edit seat and one family, with `comfy_cuda_device "2"` and `comfy_dynamic_vram "on"`, printed neither note on `gpu status` (every remaining warning once, where it had printed five times) and printed each once under `doctor`. `go build ./...`, `go vet` and `go test` on the media packages, the render suite (`node --test render/*.test.mjs`, 0 failures), `go run ./cmd/changelog check` and the leak gate pass. Tests edited to the new truth, none added: the recipe table and the 2.1 edit refusal cases in `render/multicard-recipes.test.mjs` and `render/multicard-builders.test.mjs`, the row count, the lookup case and the node-class map in `internal/mediacap/multicard_test.go`, and the placement and launch-warning cases in `internal/config/placement_test.go`.
