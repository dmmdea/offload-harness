### Fixed - the CUDA minor in llama.cpp and whisper.cpp asset names is matched, never named, so `update` and the installer find the CUDA 13 build again

- **What was wrong.** llama.cpp names its CUDA assets with the toolkit minor and moves it between releases (`cuda-13.3`, then `13.4`, and the newest releases ship `cuda-13.5`). The asset table in `internal/update/resolve.go` and `$SOURCES` in `setup/install.ps1` both named `cuda-13.4` literally (the 12.4 and 12.8 names and whisper.cpp's `12.4.0` the same way), although the table's own comment said no version number appears in it. On every CUDA 13 node `local-offload update --resolve llama` ended in `no complete release found in the newest listing pages`, so no node on that family could update llama.cpp, and a fresh install on a CUDA 13 card could not find its build in the newest release.
- **What it does.** The pattern language has one more token, `<V>`, one dotted version of digits and dots, written after a literal CUDA major (`llama-<TAG>-bin-win-cuda-13.<V>-x64.zip`). A pattern with it is an anchored regular expression over the release's asset names, in the updater and in the installer's lookup alike; the major stays literal, so the cuda12 and cuda13 families do not blur. When a release carries two minors of one major the highest wins, compared number by number (13.10 above 13.5), and the candidate's notes (the installer's console) say so. The build zip and its cudart bundle must carry the same version: a 13.5 build with only a 13.4 runtime bundle is not a complete set and the release is stepped back from, as a missing asset is. The download URL, digest, checksums lookup and journal use the matched asset's own name. A new upstream minor needs no edit.
- **Checks.** `local-offload update --resolve llama` on a CUDA 13 node names a `cuda-13.5` build of a current b-tag instead of the error. `setup/tests/install-config-seed.test.ps1` pins the new patterns and resolves them, on Windows PowerShell 5.1, against the real asset names of release b12244 (cuda13 pair to 13.5, cuda12 pair to 12.4). The two-minor and mismatched-pair cases were run once on both the Go and the PowerShell side against fake listings.
