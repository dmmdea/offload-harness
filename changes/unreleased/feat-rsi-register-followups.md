### Added - ledger rows and trace-corpus rows record which build produced them, and `ledger --failures --by-build` splits failures by build

- **Ledger stamps.** `Record`, the one path every ledger row takes to disk, stamps the build of the writing process from the same self-hash and under the same names as the delegation log: `harness_build_sha256` on a row for work the process ran itself, `delegator_build_sha256` on a delegator's row (a delegation row and its dispatch marker, and any row naming a remote node). A delegation row also carries the executing node's `harness_build_sha256` and `seat_config_sha256` from the node's result, and the node's own agent row carries `seat_config_sha256`, both only when the seat served. All three are omitted when empty; older rows still read and simply have none. No caller of `Record` changed except the delegate runner and the agent task, which hand over the two values only they hold.
- **Trace corpus.** `trace-corpus harvest` copies `delegator_build_sha256`, `harness_build_sha256` and `seat_config_sha256` from the delegation-log row into the corpus row, omitted when the log row has none. Before this the delegator build was on 17,054 of 17,095 log rows and on none of the 12,322 corpus rows.
- **Reader.** `local-offload ledger --failures --by-build` adds a `builds` key (build, job rows, failure rows, per-class counts) and a short table on stderr. A row is bucketed by the build that ran the work, else `delegator:<hash>`, else `unstamped`; the buckets add up to the report's job and failure totals. Without the flag the output is unchanged.
- **Docs.** The failure-register, mcp-server and self-improvement pages now say exactly which rows carry which stamp.
- **Check.** Built binary on the real ledger, read-only: `--by-build` puts all 10,942 failures (of 27,908 job rows) under `unstamped`, totals equal to the unsplit report, every other key identical. A classify call and two local delegations through the same binary into a scratch ledger wrote rows with the stamps, and the split showed them under that hash. `trace-corpus harvest` of the real delegation log into a scratch file: 12,291 of 12,329 corpus rows carry the delegator build, 11,652 the executing build, 10,645 the seat config.
