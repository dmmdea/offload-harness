### Fixed - a hand-run graph checks its node classes on the ComfyUI it runs on, and the docs stop pointing a named-instance box at port 8188

- **What was wrong.** `render/comfy-run-graph.mjs` ran its node-class and required-input check against `COMFY_API` or port 8188, while every other step of the same run used the endpoint the run resolved. With a named instance chosen only by `COMFY_INSTANCE`, by `--api`, or by `COMFY_CARD_UUID`, the verdict came from the owner's ComfyUI. The operator guide, the render README, the runner usage headers and the media-generation note also named 8188 for such a box, and setup Step 3 hard-coded llama-swap's default port even after `OFFLOAD_SWAP_PORT` had moved it.
- **What it does now.** The check asks the same endpoint the run uses. The operator guide names the instance port (`comfy_instance_port`, default 8189) for the idle curl and the stop recipe and says not to stop the process on 8188. The README, the runner headers (`[--api <url>]`) and the `COMFY-ENDPOINT-DOWN` text name the `comfy_instance` key, and setup Step 3 and its troubleshooting row take the llama-swap port from the config endpoint.
- **Checks.** `node --test render/preflight-graph-file.test.mjs render/comfy-run-graph.test.mjs` (34 pass); a throwaway server on a free port received the `/object_info/<class>` request when the endpoint was passed in, with `COMFY_API` pointing elsewhere; `go run ./cmd/changelog check`.
