### Added - `doctor` warns when a ComfyUI card that also drives a display has no `--reserve-vram`

- **What was wrong.** A generative edit on a 16 GB card that also drives a desktop spilled into shared memory and sampled about 60 times slower, because the runners hold back only 1.0 GiB. The 16 GB tier seeds `"comfy_extra_args": "--reserve-vram 3.0"` into a fresh config only, so an installed box never got it and `doctor` said nothing. The `--reserve-vram` help text still said "~2.0 for Hunyuan/Wan" and the setup recipe did not say that `comfy_extra_args` replaces a `COMFY_EXTRA_ARGS` from the environment. A call whose own reserve lost to the one in the extra args was silent.
- **What it does now.** `doctor` prints a `reserve:` row when a ComfyUI lane is bound, no `--reserve-vram` is in the effective extra args and the card the lane runs on drives a display (Windows only). It names the key to set, 3.0, and the replace-the-env caveat; where the display state cannot be read it says so and does not warn. The help text states the real default (1.0), the recipe in the operator guide carries the caveat, and the launch logs `COMFY-RESERVE-WARN` when a call's own reserve is overridden by the extra args.
- **Checks.** `doctor` run against a real three-card box: warns for the display card, stays silent for a headless pin or a set reserve, says UNKNOWN when the card cannot be named; the lifecycle tests pass.
