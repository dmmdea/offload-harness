### Added - the Axera AX650 NPU card is the fourth accelerator: ten tools, card telemetry, boot tuning, OCR on the card and in the fleet

- **What it does.** `axera-ax650` is an AX650-class NPU on an M.2 card with its own 4 GB (2944 MiB CMM), so its models never use host RAM or VRAM and run while the GPUs serve LLMs. Detected on Linux from `/proc/bus/pci/devices` (`1f4b0650` with the driver `ax_pcie_dev_host`), fleet-visible, served by an on-demand loopback sidecar (`accelerators/axera/`, port 18816, `axera_endpoint`, `axera_sidecar_cmd`, `axera_timeout_sec`, `axera_idle_sec`, `AXERA_HOME`, `install seed --axera-home`). Ten tools on publisher-compiled, licence-clean models: `offload_object_detect` (RF-DETR small), `offload_classify_image`, `offload_image_embed`, `offload_text_embed` and `offload_zero_shot` (SigLIP2, one 768-d space), `offload_semantic_segment` (DeepLabV3+), `offload_segment` (RF-DETR plus MobileSAM), `offload_depth` (Depth Anything 3), `offload_pose` (RF-DETR plus RTMPose-M), and PP-OCRv5 through `offload_ocr` with `engine:"npu"`.
- **Telemetry.** The card's temperature, loads, CMM, clocks, thermal trips, PCIe link and AER counters, per-process CMM and the host's fans are read through the AXCL runtime library in a child process (not the single-instance vendor CLI) and show in the sidecar's `/health`, `axera-http.sh --telemetry` (works while the sidecar is down), `offload_status` (`telemetry`, `telemetry_source`, `telemetry_error`), `/fleet/health` `accelerator_telemetry`, and the fleet UI and `top` line.
- **Tuning.** `axera-http.sh --apply-perf` pins the card CPU to its top step at every sidecar spawn, and `axera-perf.service` does it at boot; the NPU and NN-bus clocks already ship at their maxima. Measured, the pin is worth at most about 4 % and only on small models: latency is bound by the NPU and the PCIe Gen2 x2 link.
- **OCR and the fleet.** `offload_ocr` `engine:"npu"` goes Hailo first, then this box's Axera card, then a fleet node's (`fleet_accelerators`), else a defer; before, it was Hailo-only. The `accel` fleet task now returns every `<stem>_path` file the tool wrote inside the job dir as `<stem>_b64` and `<stem>_name`, so a forwarded depth map (`depth_b64`) comes back like a mask (`mask_b64`).
- **Why.** An accelerator that is not useful does not get used. The roster is chosen for licence (no AGPL), speed on the card and one embedding space; speech, an NPU LLM seat, face, person re-id and low-light are not owned, and `accelerator_tool_owners` hands the card the four names where its model is stronger (ADR 0101).
- **Check.** Measured on the card on 2026-11-10: warm latency 16-20 ms (SigLIP2 image) to 46-52 ms (RF-DETR) to 220-250 ms (instance masks); a 5-line page read exactly in 0.2-0.3 s; 23.5 RF-DETR inferences per second for 120 s at 88-89 % NPU load, 1.2 C above idle, no throttling. Details in `docs/systems/accelerators.md` and `docs/architecture/decisions/0101-axera-ax650-npu-card-as-an-accelerator.md`; recipes in `docs/OPERATOR-GUIDE.md` and `setup/SETUP-AGENT.md`.

### Security - a fleet accel job can no longer point a node's accelerator tool at the node's own files

- **What it does.** The fleet node drops a caller's `image_path` and `out_path` from every `accel` job, shipped image or not. Before, a raw job that sent both without `image_b64` kept them, so a tool's output (a mask or a depth PNG) could overwrite any file the node's service user can write; this held for every fleet-visible device. The Axera sidecar also never replaces an existing file that is not a PNG (`out_path_exists`), answers only loopback JSON clients (a 403 for a browser page or a DNS-rebinding host), and its model fetcher never forwards a token across a redirect.
- **Check.** On the card's host: a depth call over an existing text file returned `out_path_exists` and left it intact; a `text/plain` POST and a foreign `Host` both returned 403; normal calls and replacing an earlier PNG output still work. `TestBuildAccelDropsCallerPathsWithoutAShippedImage` guards the node side.
