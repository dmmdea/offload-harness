### Fixed - a seat's context window comes from its engine first, then the serving config, and the hand-written key last

- **What happened.** Two things on 2026-11-25 showed the harness trusting the hand-written `agent_ctx_tokens` key where it could have asked. A node whose serving config said `--ctx-size 49152 --parallel 1` still advertised 131072 (an operator edit left the key behind), so the delegator dealt it contracts its engine would reject, and nothing compared the two. On the reference box a seat's key said 163840 while its engine served 113600 (vLLM sizes itself at load): a run that found the seat cold spent its whole admission budget on the load, its window probe had no time left, and the run budgeted against 163840.
- **What changed.** `servedwindow.Known` decides what is believed about a seat's window without calling the engine: the window the engine last reported on this box (remembered per seat in `seat-rates.json` against a fingerprint of the serving-config entry, and used as it stands until the seat loads again, after which it can only lower the answer), else the window the serving config states for a llama.cpp seat (`--ctx-size` divided by `--parallel`, whole under `--kv-unified`), else the key. `/fleet/health` advertises it as `agent_ctx_tokens` (with additive `agent_ctx_source` and `agent_ctx_configured`), a composite node's layer rows get the same per seat, both run doors fall back on it when the probe cannot answer and remember every successful probe, `offload_status` reports it for a cold local seat, and `doctor` prints a `window:` row (informational) naming a key that disagrees with what the seat serves. A key of 0 is still never turned into an advertisement, and a node that knows nothing but the key advertises it exactly as before.
- **Cold runs.** A seat the warm-up confirmed ready now gets one short (3 s) read for its window probe even when the load spent the admission budget. A run whose probe still failed re-reads the window once, loaded-only, after its first answered call, replaces its budget with it and says so in `ctx_window_note`; a run whose probe answered is unchanged. The fleet node reads the window once, loaded-only and off the health path, when its agent seat goes from not ready to ready.
- **Check.** One run: a serving config entry with `--ctx-size 49152 --parallel 1` and a key of 131072 resolves to 49152 (`serving_config`), then to what the engine reported once one is remembered. Details: [ADR 0106](docs/architecture/decisions/0106-a-seats-window-is-the-one-its-engine-serves.md).
