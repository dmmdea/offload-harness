### Fixed - the failure register files a lease hold, a loop cancellation and a node's folder fault under the class that names them

- **What was wrong.** Three writers filed real failure rows under a class that does not describe them, and two sentences sat in `other`. A delegation to a local seat held by a text lease (`local seat reserved (gpu lease ...)`) was `infrastructure`, though it is a capacity hold and not a fault. The agent loop's `agent loop: canceled (the parent context ended ...)` was `budget`, though the closed set has `canceled`. A node's own folder failure (`agent contract: creating pipeline-jobs dir: ...`, which reaches the delegator as an ack-time 400) was `dispatch_refused`, a class defined as a fact about the request or the credentials, though the fault is the node's configuration. In `other`, a node's `a text lease holds its card; it may take the call later` is a capacity signal, and the browse door's own typed errors name classes.
- **Where each now goes.** The lease hold is `node_busy` (the class defined as the seat or card being held by other work; `capacity_wait` is the delegator finding no node with room, a different cause with a different fix). The loop cancellation is `canceled`. The folder fault is `config` (the node's configured home does not exist on that machine; `infrastructure` is for a part of the stack that failed while configured right). The node's lease sentence, matched whole, is `node_busy`; the browse door's `BROWSER_UNAVAILABLE` and `DECISION_UNAVAILABLE` are `infrastructure`, `HOST_NOT_ALLOWED` is `contract` and `budget` is `budget`. The browse door's `blocked` ties to no one class and stays in `other`.
- **How.** One function, `RefileStamped` in `internal/ledger/reasoncode.go`, holds the three misfilings, each needing both the old stamp and the writer's own sentence. `Record` applies it when it settles a row's code, so new rows are stamped right; the register applies it when it reads, so rows already in the ledger are counted right (they count in `class_derived_rows`; the ledger file is not rewritten). The five other sentences are rules in `DeferCode`. The wire defer class of the lease-hold defer is unchanged, so the exit code and the run summary still count it as infrastructure. No class is renamed and the JSON shape of `ledger --failures` is unchanged.
- **One exception, on purpose.** A lease hold whose remote fallback failed on a fault (every remote failed its health probe, no remote is configured, none passed the capability gate, or one advertises no context ceiling) stays `infrastructure`: a held local seat must not hide a dead or misconfigured fleet. A row that names a fault keeps the fault class even when other remotes were only full. On the real ledger, 30 days: of the 72 lease-hold rows the report counts, 55 name only remotes without room and move to `node_busy`; 17 also say another remote failed its health probe and stay `infrastructure`.
- **Docs.** The root-cause entries in `internal/ledger/rootcause.go` and the table on the failure-register page say what was fixed and that older rows are corrected at read time.
- **Check.** The built binary and the installed one, both read-only on the real ledger, `ledger --failures --since 30`: 2,566 failure rows of 8,784 job rows in both, no row added or lost. `infrastructure` 195 to 140, `budget` 250 to 236, `dispatch_refused` 145 to 115, `other` 55 to 30, and `node_busy` 628 to 704, `canceled` 29 to 46, `config` 2 to 32, `contract` 4 to 5. Every other class is unchanged, and the stack-fault share falls from 0.1142 to 0.1044 because the lease holds were counted as stack faults before.
