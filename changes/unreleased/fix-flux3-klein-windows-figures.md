### Fixed - the `flux3-klein/bf16` card-only row's Windows figures are the render's process-tree peaks (13 GiB touched, 19 GiB of commit), not a slow poll's reading of one process

- **What was wrong.** 0.212.0 gave the row `hostWindowsGiB {touched 12, commit 16}` from a 4 s poll of the ComfyUI process alone (11.24 GiB working set, 15.45 GiB private). The harness's own footprint sampler reads the render's whole process tree every 500 ms (`gpulease.TreeMemory`), and for the same run it recorded 12.3 GiB resident and 18.2 GiB private; a second run on the release build (1024x1024, 16 steps, seed 21, 182.1 s) recorded 12.3 and 18.3 GiB. The slow poll missed the commit peak, which falls at the start of the VAE decode: the decode's buffers land on the storage card while the DiT is still committed, and WDDM backs both with system commit. So the stated commit was about 2.3 GiB under what a render holds.
- **What it does.** `internal/mediacap/multicard.go` and `render/multicard-recipes.json` carry `{touched 13, commit 19}` (the tree's two peaks rounded up to whole GiB), and the row's evidence names both instruments. A FLUX 3 Klein bf16 call under `--placement multicard` on a Windows host with two fitting cards now declares 13 GiB touched and 19 GiB of stated commit. Linux is unchanged (0).
- **Seen on the release.** On `<node-b>` the first call after 0.212.0 declared 18.0 GiB of host RAM and 18.0 GiB of commit, not the row's figures: `calibratedRAM` raises a non-zero declaration to the 90th percentile of the last 20 recorded runs' resident peaks when that is higher, and that node's window still held runs from before 0.210.0's read-only encoder load (16.9-18.1 GiB resident). The row's figure is the floor that the declaration falls to as those runs age out, which is why the commit figure has to be right. `docs/systems/media-generation.md` now says a non-zero row figure is a floor.
- **Checks.** The existing parity pin and `TestAMeasuredCardOnlyRowDeclaresItsWindowsFiguresOnlyOnAWindowsHost` carry the new figures; no new test.
