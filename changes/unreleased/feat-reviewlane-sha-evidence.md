### Added - `offload_review_diff` results are bound to the diff they judged: SHA-bound evidence, a NOT_RUN outcome, gates before the seat, a second fingerprint check and a durable trace (RSI-OH-4)

- **What it does.** A review used to say what a seat thought and nothing about what it thought it about, and a finding the caller skipped left no record. Every `offload_review_diff` payload, deferrals included, now carries an `outcome` and an `evidence` block (new file `internal/reviewlane/evidence.go`). `evidence` holds the sha256 of the diff bytes (`diff_sha256`, `diff_bytes`), the optional `base_sha` and `head_sha` the caller passes (hex, echoed and never resolved: the lane has no git access, and the bytes cannot be mistyped the way a commit id can), `prompt_sha256` (the exact prompt the seat was shown), `gates` (the deterministic gate receipts) and `seat` (the seat receipt: seat, node, executed-on, steps, stop reason, the digest of its raw answer, no timing). `outcome` is one of `PASS`, `FINDINGS`, `GATE_FAILED`, `NOT_RUN` or `STALE`, chosen in one function (`reviewlane.Decide`), with an `outcome_reason` for everything but `PASS` and `FINDINGS`.
- **NOT_RUN, and what PASS needs.** `NOT_RUN` means no clean seat reviewed the diff, and it is never a `PASS`: every deferral, a runner error, a refused binding (malformed commit id or receipt), a result with no seat receipt, an answer that read as NONE while every line it wrote was discarded, and a diff over `MaxDiffBytes`. The oversize rule lives in `Decide` as well as in the contract builder, so a caller that skips the builder cannot reach `PASS` with an unreviewed diff. `PASS` needs a seat with a receipt, a diff inside the ceiling, every gate receipt green and for the reviewed commit, an unchanged diff at the second check, and the seat's own NONE.
- **Gates run first.** `evidence.gates` is built before any seat is contacted, so even a refusal is bound to the bytes it refused. The lane's own gates (`diff-size`, `conflict-markers`: a merge-conflict marker on an added line) come first, then the `gate_receipts` the caller hands over, the results of lints and tests it ran itself (`name`, `status` pass or fail, `detail?`, `head_sha?`, at most 16). The lane executes nothing a caller names, so the review door does not become a command-execution surface. A receipt for a different head commit is marked `stale` and cannot support a `PASS`. A red gate does not stop the seat (the lane stays advisory and the findings of a diff that fails a lint are still worth reading); it turns a clean answer into `GATE_FAILED`.
- **Second fingerprint check.** Right before the result is returned (`reviewlane.Seal`), a `diff_path` is re-read through the same confined reader and compared with the first fingerprint (`recheck_sha256`). A difference, or a file that can no longer be read, makes the result `STALE`: the findings are about bytes that no longer exist. An inline diff is held in memory and cannot move.
- **Advisory findings always leave a trace.** Each sealed review appends a `review` row and one `finding` row per published finding (severity, file, line, the claim and why cut to 512 bytes, and a digest of the whole finding) to `review-evidence.jsonl` in the harness home, beside the ledger, whether or not anyone reads or applies the findings. A failed write is reported as `trace_error` on the result. It is a sidecar and not a ledger row on purpose: every ledger reader counts a row as a call or a job, the pipeline already writes the run's own row (door `offload_review_diff`) before the outcome is known, and the ledger keeps hashes where this trace keeps the short finding text.
- **Stays advisory; one source is skipped.** An outcome is a label on a result a lead reads; nothing here blocks a merge or a commit. The import-graph atlas that the source material also describes is skipped. All new JSON is additive (new keys, `omitempty` inside `evidence`), the deferral shape and the findings are unchanged, and the seat's prompt is still the task and the diff and nothing else.
- **Tests.** Red first (commits `test(reviewlane)` and `test(mcpserver)` before the implementation). `internal/reviewlane/evidence_test.go`: NOT_RUN with no clean seat (five shapes), PASS refused when oversize (and allowed at exactly the ceiling), the fingerprint is the sha256 of the bytes and changes with them, a recheck that disagrees is STALE, gates attach before any seat receipt and a red one blocks `PASS`, a receipt for another commit cannot support `PASS`, the lane's own gates, refused bindings, the seat receipt carries no timing, the evidence JSON omits what is unknown, a trace row exists for an advisory finding (and for a NOT_RUN), the recheck runs once inside `Seal` and not when no seat ran, an unwritable trace is loud, trace text is bounded and rune-safe. `internal/mcpserver/reviewevidence_test.go`: the door end to end (bound result and trace, clean PASS, every deferral NOT_RUN, oversize, refused bindings never reach the seat, red gate, a `diff_path` rewritten or deleted during the review is STALE, the advertised schema). Nine mutations of `evidence.go` and four of the handler were each caught by a named test.
- **Where.** `internal/reviewlane/evidence.go` (new), a small hunk in `handleReviewDiff` (three optional inputs, the seal at each exit, `publishReview` folded into a local `publish` step), the tool's input schema and description, `docs/systems/mcp-server.md`, and the `README.md` row.
