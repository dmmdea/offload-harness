### Added - `offload_review_diff` results are bound to the diff they judged: SHA-bound evidence, a NOT_RUN outcome, gates before the seat, a second fingerprint check and a durable trace (RSI-OH-4)

- **What it does.** A review used to say what a seat thought and nothing about what it thought it about, and a finding the caller skipped left no record. Every `offload_review_diff` payload, deferrals and early refusals included, now carries an `outcome` and an `evidence` block (new file `internal/reviewlane/evidence.go`). `evidence` holds the sha256 of the diff bytes (`diff_sha256`, `diff_bytes`), the optional `base_sha` and `head_sha` the caller passes (hex, echoed and never resolved: the lane has no git access, and the bytes cannot be mistyped the way a commit id can), `prompt_sha256` (the exact prompt the seat was shown), `gates` (the deterministic gate receipts) and `seat` (the seat receipt: seat, node, executed-on, steps, stop reason, whether the node filed the run as a deferral, the digest of its raw answer, no timing). `outcome` is one of `PASS`, `FINDINGS`, `GATE_FAILED`, `NOT_RUN` or `STALE`, chosen in one function (`reviewlane.Decide`), with an `outcome_reason` for everything but `PASS` and `FINDINGS`.
- **NOT_RUN, and what PASS needs.** `NOT_RUN` means no clean seat reviewed the diff, and it is never a `PASS`: every result with `deferred: true`, a runner error, an early refusal (both `diff` and `diff_path`, neither, a `diff_path` that cannot be read or is over its cap, a bad `read_root`, arguments that do not decode), a refused binding (malformed commit id or receipt), a result with no seat receipt, an answer that read as NONE while every line it wrote was discarded (the `dropped_*` counts become the filtered total inside `Seal`), a diff over `MaxDiffBytes`, and a run the node filed as a deferral whose answer the lane read as a clean NONE. The salvage still publishes what such a run wrote and findings read from it stay `FINDINGS`; only its clean NONE is never an all-clear, and `seat.deferred` records the attempt. A review refused before any diff was read is a diff-less `NOT_RUN`: `diff_bytes` is 0, there is no `diff_sha256`, the refusal is `evidence.refusal` and `outcome_reason`, and the deferral shape and reason are the ones the door always gave. The oversize rule lives in `Decide` as well as in the contract builder, so a caller that skips the builder cannot reach `PASS` with an unreviewed diff. `PASS` needs a seat with a receipt, a diff inside the ceiling, every gate receipt green and for the reviewed commit, an unchanged diff at the second check, and the seat's own NONE.
- **Gates run first, and the lane runs no lints or tests itself.** `evidence.gates` is built before any seat is contacted, so even a refusal after the diff was read is bound to the bytes it refused. The lane's own gates (`diff-size`, `conflict-markers`: a merge-conflict marker on an added line) come first, then the `gate_receipts` the caller hands over, the results of lints and tests it ran itself (`name`, `status` pass or fail, `detail?`, `head_sha?`, at most 16). Those receipts are the caller's word, which the lane cannot verify, and it executes nothing a caller names, so the review door does not become a command-execution surface. A receipt for a different head commit is marked `stale` and cannot support a `PASS`; once the review names a head, a receipt that names no commit is marked `unbound` and cannot either (a review with no head has nothing to compare, and its receipts stand as given). A red gate does not stop the seat (the lane stays advisory and the findings of a diff that fails a lint are still worth reading); it turns a clean answer into `GATE_FAILED`.
- **Second fingerprint check.** Right before the result is returned (`reviewlane.Seal`), a `diff_path` is re-read through the same confined reader and compared with the first fingerprint (`recheck_sha256`). A difference, or a file that can no longer be read, makes the result `STALE`: the findings are about bytes that no longer exist. An inline diff is held in memory and cannot move.
- **Advisory findings always leave a trace, and the trace is the durable record.** Each sealed review appends a `review` row and one `finding` row per published finding (severity, file, line, the claim and why cut to 512 bytes, and a digest of the whole finding) to `review-evidence.jsonl`, whether or not anyone reads or applies the findings. The path is derived from the configured ledger file (`reviewlane.TracePathFor`: the ledger's directory, the harness home when no ledger path is set), so it always sits beside the ledger wherever the operator placed it. A failed write is reported as `trace_error` on the result. No ledger row is written for the verdict, on purpose: every ledger reader counts a row as a call or a job, the pipeline already writes the run's own row (door `offload_review_diff`) before the outcome is known, and the ledger keeps hashes where this trace keeps the short finding text.
- **Stays advisory; one source is skipped.** An outcome is a label on a result a lead reads; nothing here blocks a merge or a commit. The import-graph atlas that the source material also describes is skipped. All new JSON is additive (new keys, `omitempty` inside `evidence`), the deferral shape and the findings are unchanged, and the seat's prompt is still the task and the diff and nothing else.
- **Tests.** Red first (commits `test(reviewlane)` and `test(mcpserver)` before the implementation, twice: once for the feature and once for the adversarial review's findings). `internal/reviewlane/evidence_test.go`: NOT_RUN with no clean seat (five shapes), a diff-less refusal, a node-deferred clean NONE (and its findings staying `FINDINGS`), the `dropped_*` counts through `Seal` one key at a time, the seat receipt's provenance through `Seal`, PASS refused when oversize (and allowed at exactly the ceiling), the fingerprint, a recheck that disagrees is STALE, gates attach before any seat receipt and a red one blocks `PASS`, a receipt for another commit or naming none cannot support `PASS`, the lane's own gates and the closing conflict marker, refused bindings and the receipt and commit-id bounds, the trace path beside the ledger, distinct `review_id` values, the seat receipt carries no timing, the evidence JSON omits what is unknown, a trace row exists for an advisory finding (and for a NOT_RUN), the recheck runs once inside `Seal`, an unwritable trace is loud, trace text is bounded and rune-safe, and the owner-only trace file mode (a Unix-only test). `internal/mcpserver/reviewevidence_test.go` and `reviewfence_test.go`: the door end to end (bound result and trace, clean PASS, every deferral NOT_RUN, every early refusal sealed, oversize, refused bindings never reach the seat, red and unbound gates, a `diff_path` rewritten or deleted during the review is STALE, the trace beside a ledger kept away from the home, the advertised schema) and both fenced-seat call sites (the fleet's delivered review and the salvaged deferral, with executed-on, node and trace rows). Nineteen mutations of `evidence.go` and eleven of the handler, drawn from the review's survivors and the new rules, are each caught by a named test, except the file-mode one whose test only runs on Unix.
- **Where.** `internal/reviewlane/evidence.go` (new), a hunk in `handleReviewDiff` (three optional inputs, the seal at each exit including the early refusals, `publishReview` folded into a local `publish` step, the trace path from the ledger path), the tool's input schema and description, `docs/systems/mcp-server.md`, and the `README.md` row.
