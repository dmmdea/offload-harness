### Added - `active_backend` per lane and per seat in `doctor` and `/fleet/health`: which engine answers, the chain it was picked from, the probe behind it, and why

- **What it does.** Every lane (workhorse, agent, triage, escalation, reasoning, vision, ocr, stt) and every seat now carries four engine-neutral fields: `active_backend` (an engine kind: `llama.cpp`, `vllm`, `rkllm`, `strata` reserved for the Strata seat, `unknown` when the config does not name the engine, or `none`), `backend_chain` (the engine kinds it may use, in preference order), `backend_probe` (`process`, `endpoint` or `completion`) and `backend_reason` (why that backend was chosen, or why none was; a lane served by its second backend names the first one's failure). `local-offload doctor` prints them in a new `backends:` section after its own checks, whatever they returned, so an unreachable llama-swap still gets rows that say `none` and why. `/fleet/health` gains `lane_backends` and `seat_backends` with the same rows. Both are additive and `omitempty`; the existing `backends` key (hardware tags, ADR 0054) is unchanged.
- **The agent lane of a vLLM tier is a real chain.** A box installed as a tier that declares a vLLM agent seat reports `[vllm seat, llama.cpp fallback]`: when the vLLM seat is not served (its venv is not installed) the lane reports the fallback as active and says why, and a seat that answers while the lane is bound to another says so. It reports which backend can serve now, in preference order; it does not route.
- **The default probe loads nothing.** It reads llama-swap's roster and running list, and asks a seat that is already loaded and ready for its own health endpoint at the seat's own address, never through `/upstream` (which loads on demand and resets the idle timer). A seat that is in the roster and not loaded is reported available on demand and is not asked anything. No code path of the default probe sends a completion.
- **`doctor --probe-completion` is the only door to a completion.** One 1-token completion per seat, which can load an idle seat, so it is a flag a person passes: it is skipped, with the reason in the row, wherever it would load a seat while a vLLM seat holds the cards, and whenever llama-swap's running list cannot be read. `/fleet/health` never runs it.
- **`/fleet/health` never waits for the report.** It is a cached background read like the residency answer: the first request after start-up answers without the keys (absent means unknown, never `none`) and kicks one read, and a read older than 30 s is refreshed behind the next request. Reasons carry no address, path or command line.
- **Engines register in one place.** A new engine adds one row to the classification table in `internal/backendchain/classify.go` and changes no field.
- **Code.** New package `internal/backendchain`; `servingtmpl.SeatEntries`; `internal/fleetnode/activebackend.go`; `doctor_backends.go` (the `doctor` verb wrapper, so `main.go` carries one changed line, and a tier-table hook installed in `init`, so the fleet wiring costs `main.go` nothing).
- **Tests.** Red first (the failing tests were committed before the implementation). A resolver table (a failing first backend falls to the second and the reason names the failure; every backend failing is `none` at the deepest probe; an unknown engine is never guessed); a fake llama-swap that fails the test on any completion, any `/upstream` path and any POST, run by `Collect`, by the `/fleet/health` refresh and by the `doctor` verb; the completion probe only with the flag, once per seat, 1 token; the vLLM no-evict skip and the unreadable-running-list skip; an alias-bound seat read as loaded; `checkEndpoint: none`; the additive-JSON shape; doctor's flag parse. Two existing tests that count the residency refresh's llama-swap reads stand the new collector down, since its own reads are pinned where it is tested.
- **Docs.** `docs/systems/fleet-node.md` (the new section, the health route row, the source map), `docs/FLEET-NODE.md`, `docs/OPERATOR-GUIDE.md`.
