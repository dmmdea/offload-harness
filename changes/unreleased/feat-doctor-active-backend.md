### Added - `active_backend` per lane and per seat in `doctor` and `/fleet/health`: which engine answers, the chain it was picked from, the probe behind it, and why

- **What it does.** Every lane (workhorse, agent, triage, escalation, reasoning, vision, ocr, stt, stt_hq) and every seat now carries four engine-neutral fields: `active_backend` (an engine kind: `llama.cpp`, `vllm`, `rkllm`, `strata` reserved for the Strata seat, `unknown` when the config does not name the engine, or `none`), `backend_chain` (the engine kinds it may use, in preference order), `backend_probe` (`process`, `endpoint` or `completion`) and `backend_reason` (why that backend was chosen, or why none was). A lane is a route `doctor` already diffs against the roster that has an effective seat: a route with no effective seat is not a lane, `embed_model` never is, and `agent` and `ocr` report the seat they fall back to when their own model is unset. `local-offload doctor` prints the fields as text rows in a new `backends:` section after its own checks, whatever they returned, so an unreachable llama-swap still gets rows that say `none` and why. `doctor` has no JSON mode: the text rows live in `doctor`, and the JSON of the same fields is `lane_backends` and `seat_backends` on `/fleet/health`. Both are additive and `omitempty`; the existing `backends` key (hardware tags, ADR 0054) is unchanged.
- **On a lane, `active_backend` is the engine of the seat the lane is bound to.** The agent lane of a box installed as a tier that declares a vLLM agent seat has the chain `[vllm seat, llama.cpp fallback]`, but the lane routes to whichever seat `agent_model` binds, so that seat's engine is what answers. A preferred seat that is up while the lane is bound to another is named in the reason (`the preferred vllm seat X is available (...) but does not answer for this lane, which is bound to Y`) and is not the active backend; a preferred seat that failed is named before the answer (`vllm seat X unavailable: ...; fell to llama.cpp seat Y: ...`); a bound seat that fails is `none`, with the other seat reported as available but not bound. It reports what answers for the lane as configured; it does not route.
- **The default probe loads nothing.** It reads llama-swap's roster and running list, and asks a seat that is already loaded and ready for its own health endpoint (the entry's `checkEndpoint`, `/health` when it states none) at the seat's own address, never through `/upstream` (which loads on demand and resets the idle timer). A seat that is in the roster and not loaded is reported available on demand and is not asked anything. No code path of the default probe sends a completion.
- **`doctor --probe-completion` is the only door to a completion, and `doctor -h`, the usage line and the usage a mistyped flag prints list it.** A flag the verb does not accept is refused with the flag package's error line, the same usage as `doctor -h` and exit status 2, before any check runs (the verb's own flag set is checked before `runDoctor`, whose flag set knows only `--config`). One 1-token completion per seat, which can load an idle seat, so it is a flag a person passes. It is refused, with the reason in the row, for any seat that is not running while a vLLM seat is loaded or loading (a vLLM seat included: loading one evicts another) and whenever llama-swap's running list cannot be read. The decision uses a fresh read of the running list and the list is read again after every completion, so a vLLM seat the run loaded itself, or another client loaded meanwhile, stops the completions that would follow. A row that ran a completion on an idle seat says the completion loaded it, and one that another client loaded meanwhile says so. `/fleet/health` never runs it.
- **`/fleet/health` never waits for the report.** It is a cached background read like the residency answer: the first request after start-up answers without the keys (absent means unknown, never `none`) and kicks one read, and a read older than 30 s is refreshed behind the next request. Reasons carry no address, path, URL or command line, and the new keys add no host name, path or IP to what `backends` already exposes: engine kinds, probe levels, each lane's status key, and seat names (model ids and aliases), which `served_models` already publishes on a node with the agent or chat lane on.
- **Engines register in one place.** A new engine adds one row to the classification table in `internal/backendchain/classify.go` and changes no field.
- **Code.** New package `internal/backendchain`; `servingtmpl.SeatEntries`; `internal/fleetnode/activebackend.go`; `doctor_backends.go` (the `doctor` verb wrapper, so `main.go` carries one changed dispatch line and one usage line, and a tier-table hook installed in `init`, so the fleet wiring costs `main.go` nothing).
- **Tests.** Red first (the failing tests were committed before the code) for the resolver, the collector, the bound-seat and completion-probe corrections and the usage a mistyped flag prints; the `doctor -h` help, the cache-age test and the tests that pin existing collector behavior (the reason text of the vLLM-holder skip and of an unreadable running list, the re-read after a failed completion, the reason once an unreadable running list reads) were proven by mutating the code they pin instead. A resolver table (the bound seat answers for its lane, a failing preferred backend falls to the bound one and the reason names the failure, a bound backend that fails is `none`, every backend failing is `none` at the deepest probe, an unknown engine is never guessed); a fake llama-swap that fails the test on any completion, any `/upstream` path and any POST, run by `Collect`, by the `/fleet/health` refresh and by the `doctor` verb; the completion probe only with the flag, once per seat, 1 token; a fake that loads (and evicts) on completion, proving the probe stops once it has loaded a vLLM seat, re-reads `/running` after each completion and refuses a second vLLM seat; the reason text of a completion row; the seat's own `checkEndpoint` path; an unset `agent_model`, an unset `ocr_model` and `stt_hq` as lanes, and `embed` as no lane; no reason carries a path, URL, route or address across every failure clause (an unreadable running list, by status and by transport failure, and the vLLM-holder skip included; each scenario asserts its clause appeared); a stale cached read refreshed behind the next request; the unreadable-running-list skip; an alias-bound seat read as loaded; `checkEndpoint: none`; the additive-JSON shape; doctor's flag parse and its help. Two existing tests that count the residency refresh's llama-swap reads stand the new collector down, since its own reads are pinned where it is tested.
