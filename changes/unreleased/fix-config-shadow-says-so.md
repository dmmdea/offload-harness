### Changed - a command that reads ./config.json while the home config also exists says so on stderr

- **What was wrong.** Config resolves flag > `$LOCAL_OFFLOAD_CONFIG` > `./config.json` > `~/.local-offload/config.json`. A command run from a directory holding a `config.json` (a checkout of this repo keeps an untracked dev one at its root) read that file instead of the machine's real config and reported the wrong bindings as the machine's (a recipe readback said a family was unmatchable; `delegate` said delegation was disabled), with nothing naming the file it read.
- **What it does.** When the config came from the current directory (no flag, no environment variable), `~/.local-offload/config.json` also exists, and the two are different files (`os.SameFile`, so a symlink or the same path does not trigger it), every config-loading verb and `local-agent` print one line to stderr, once per process, naming both files and the ways out: `NOTE: config read from ./config.json in the current directory (<path>); <home>/.local-offload/config.json also exists and was NOT read. Pass --config <path>, set LOCAL_OFFLOAD_CONFIG, or run from another directory to use it.` `doctor`'s `config:` line carries the same fact, and `config.Source.ShadowedHome` records it. Precedence is unchanged, and the MCP server's stdout is untouched (stderr only).
