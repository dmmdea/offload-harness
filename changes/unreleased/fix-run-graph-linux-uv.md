### Fixed - run-graph installs node packs on a Linux node, and never replaces the venv's torch build

- **What was wrong.** The step that brings a graph's node packs onto a node looked for `uv.exe` beside the ComfyUI venv's python on every platform, so a Linux node with uv installed deferred `SATISFIER_UNAVAILABLE: uv not found in the ComfyUI venv` on every graph that names a pack. Past that, three more things stopped a Linux node. A venv that `uv venv` created has no pip, and the step asked `python -m pip` for the freeze, the check and the install. The packs' lock was resolved against PyPI alone with torch held by its public version; off Windows a CUDA torch wheel depends on the CUDA runtime wheels, and PyPI's build of the same number can pin another CUDA release, so the install replaced torch to match (seen on a node with two 16 GB cards: `2.15.0+cu134` became PyPI's `2.15.0`, a cu132 build, and ten CUDA libraries went down with it; the build was put back by hand). And `uv pip check` reports a wheel whose own tag is wrong (`decord 0.6.0`: "was built for a different platform") as an incompatibility, which rejected the pack that asked for it.
- **What it does now.** uv is taken from beside the venv's python (`uv.exe` on Windows, `uv` elsewhere) or from `PATH`. A venv with pip is asked exactly as before; one that answers "No module named pip" is served through `uv pip <verb> --python <venv python>`. Off Windows, a torch build with a label (`+cu134`, `+cpu`, `+rocm…`) is resolved with its own PyTorch index beside PyPI and held at its full version, so the lock names the installed build and its own runtime; a lock that would still replace torch, torchvision, torchaudio or numpy is refused before anything is installed. The wheel-tag line and uv's status lines are not counted as conflicts. On Windows nothing changes: the lookup, the public pins and the pip calls are the same. The deferral text now reads "uv not found beside the ComfyUI venv's python or on PATH (install uv)".
- **Not done.** A failed install still leaves what it installed in the venv; only the cloned pack folders are removed.
- **Checks.** `node --check`; the pure helpers read once against the lines the node printed; on that Linux node (uv-created venv, torch `2.15.0+cu134`, Ubuntu 26.04) one `run-graph` with a manifest naming two packs and four model files: both packs cloned and installed, torch and the CUDA wheels unchanged afterwards, the graph's cutout written.
