### Fixed - the media queue listing no longer shows a waiting ticket whose owner process is gone

- **What was wrong.** `offload_status` section `media_queue` listed two tickets from three weeks earlier: state `waiting`, `owner_alive: false`, `holds_place: true`, and a `why` sentence written while the owner was alive ("1 caller(s) hold a place in line ahead of this call ..."). A reader took that for a dead caller keeping a place in line for a card. The queue's own rule is that a dead owner's waiting ticket is debris, but the sweep that removes it ran only inside a scan cycle of a process that has a waiting ticket itself, so on a machine where nobody queued for weeks the debris stayed on file and in the listing.
- **What it does.** `mediaremote.Queue` now sweeps before it lists, and drops the places the sweep returns from the lease line the way the scan cycle does (it takes the status server's runner for that). A dead owner's waiting ticket is gone from the listing and from disk after one `offload_status` call. A dead owner's ticket that was already placed on a node, or is in flight, is unchanged: it is kept for `deadKeep` so the next identical call adopts it, and the listing shows it with `owner_alive: false` until then.
- **Checks.** One case added to `TestSweepRemovesDebrisAndTheRowMemoryForgetsAGoneNode`; no new test.
