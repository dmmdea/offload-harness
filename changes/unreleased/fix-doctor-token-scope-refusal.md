### Fixed - `doctor` no longer reads a node's caller-scope refusal as "no token"

- **What was wrong.** `doctor`'s fleet-token rows read every 403 answer to the token probe as `NO-TOKEN`: "it listens beyond loopback with no fleet_auth_token ... set the same token on the node". A node that sets `fleet_admit_scopes` checks the bearer first and then refuses an asker whose scope it does not admit, with a typed 403 (`"refusal":"scope_not_admitted"`). The probe declares no scope, so a personal-only node that holds the right token was reported as holding none, and the advice was to set a token it already had.
- **What it does now.** `rosterprobe.ClassifyToken` reads the typed `refusal` field (never the message text): a 403 carrying `scope_not_admitted` is a bearer that passed, and the row reads `OK`. Every other 403 still reads `NO-TOKEN`.
- **Checks.** The token probe against the real node handler with `fleet_admit_scopes: ["personal"]`: its own token answers 403 `scope_not_admitted` and classifies as accepted; another token still answers 401. On the reference box, `doctor` from a build with the fix reads the personal-only node as `OK`, where 0.222.0 printed `NO-TOKEN`; the other rows are unchanged. Doctor's existing fleet-token tests pass.
