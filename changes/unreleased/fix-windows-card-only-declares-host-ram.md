### Fixed - a measured card-only recipe with no Windows figures no longer declares 0 host RAM on a Windows host, nor does a card-only video or animate call

- **What was wrong.** A card-only (`--placement multicard`) row that was measured declared 0 host RAM on every host. The 0 is a Linux measurement: there the read-only map's pages are clean file pages `MemAvailable` already counts. On a Windows host the same render holds real memory, the map's pages in the working set and the card allocations in system commit: this box's own footprint records show a krea2 card-only render at 27 GiB resident and 31 GiB of commit, and a qwen-image one at 16.6 and 24.5 GiB, while the door declared 0 for both. Only `flux3-klein/bf16` carried Windows figures. The card-only video and animate calls (`ltx25`, `wan22`, `wan-animate2` under `--wan-placement multicard` / `--placement multicard`) declared 0 the same way, from zeros measured on Linux nodes only: the one Windows run the footprint sampler has of them, an `ltx25` clip, held 23.0 GiB resident and 29.4 GiB of private bytes.
- **What it does.** On a Windows host a measured card-only row that fits the two leased cards but carries no `hostWindowsGiB` keeps the ordinary estimate, and the declaring line says why: its 0 was measured on a Linux host and no run has measured what a Windows host holds for it. Once a run on Windows has measured a row, its figures go in `render/multicard-recipes.json` (`hostWindowsGiB`) and the row declares them, stated, as `flux3-klein/bf16` does. The card-only video and animate calls do the same: on a Windows host a call that fits the two leased cards declares the figures a Windows run of its family measured (`videoWindowsFigures` in `internal/hostneed/hostneed.go`), stated, and a family with no entry keeps the ordinary estimate, the whole set, with the reason. `ltx25` has its entry: 24 GiB touched and 30 GiB of commit, from one 448x832 clip of 49 frames on two 16 GiB cards from a cold instance (23.0 GiB resident and 29.4 GiB of private bytes at the peak, while the door declared 0). The figures stand for a weight set no larger than the measured one, within 5 percent. `wan22` and `wan-animate2` have none yet. Linux is unchanged (0, marked card-only for images).
- **Checks.** `TestAMeasuredCardOnlyRowDeclaresItsWindowsFiguresOnlyOnAWindowsHost` carries the new case, and `TestTheResidentShareIsReadFromTheCall` carries the fitting `ltx25` call on a Windows host (the measured figures, stated). The tests that pin the Linux zero now say Linux (`imgFacts`, `wanFacts` and `ltxFacts` set `GOOS`; the pipeline tests that run the real door expect the zero only off Windows).
