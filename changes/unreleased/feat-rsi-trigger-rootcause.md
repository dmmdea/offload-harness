### Added - the recipe proposer's trigger is a printed count of measured runs, and every failure class carries a root cause and an action

- **Proposer trigger (ADR 0036, amendment 2026-11-12).** The trigger for building the recipe proposer read "trace-bearing runs in the hundreds", and the corpus has 10,766 of those. The runs a proposer can learn from carry a measured pager report (`pager.measured_runs`: the loop evicted something, so the re-fetch question has an answer for that run), and the corpus has 31 of 12,332. The trigger is restated on that count, as a dated amendment, and the verb prints it: `trace-corpus trigger --corpus FILE` prints JSON (`needed`, `have`, `met`, the trace-bearing and total counts, the largest single seat's count) and `trace-corpus readout` prints the same as one stderr line. On the real corpus it reads `needed 100 / have 31 / NOT MET`; the largest single named seat has 10. The readout report itself is unchanged, so a frozen baseline still reproduces. The seat's frozen pre-registration, the other half of the trigger, is not in the corpus and is not judged. No proposer is built.
- **ADR 0091** is Accepted: the verb, the harvest, the readout and the pager and pass-count recording shipped in 0.206.0. Its status note records that the pager gate now reads `BELOW_GATE` on 31 runs (8 of 86 evicted payloads re-fetched) where its first readout read `NO_DATA`, and that 31 runs do not settle the `edit_context` question.
- **Root causes.** `internal/ledger/rootcause.go` holds, for each of the 31 failure classes, a cause kind (capacity signal, node configuration, harness defect, caller contract, upstream service, unknown), a root cause, the evidence (the emitting function and the 30-day count) and an action. `ledger --failures` prints them with each class as `classes[].cause` in the JSON and as text on stderr, with `causes_not_investigated` listing the open classes present in the window; the existing fields are unchanged. Where the code and the rows do not settle a cause the entry says `not investigated` and what would settle it: 15 of the 31 classes (4 of the 19 in the last 30 days), never a guessed cause. The table is on the failure-register page.
- **Check.** Built binary on the real corpus and ledger, read-only: `trace-corpus trigger` prints `needed 100 / have 31 / NOT MET` of 10,766 trace-bearing and 12,332 runs, matching the installed 0.232.0 build's counts; `ledger --failures --since 30` prints all 19 classes in the window with cause and action, 4 not investigated (`failed_verification`, `other`, `poll_deadline`, `stall_cold_load`), and every pre-existing field matches the build before the change apart from live rows written in between.
