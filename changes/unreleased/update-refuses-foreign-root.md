### Fixed - `update` run as root refuses an install root that another user owns

- **What was wrong.** `sudo local-offload update --component sdcpp` on a Linux node whose install root belongs to an ordinary user took the lock and wrote everything as root: the lock file, the version folders, the new generation, the live link and `installed.json`. The user's next plain update could then no longer prune the root-owned generation, and the freshly downloaded build ran its self-check as root.
- **What it does now.** A changing run (not `--dry-run`, not `--resolve-only`) as root against a root owned by another user stops before the lock with exit 2 and nothing written. The message names the owner and the command to use, `sudo -u <owner> local-offload update ...`; for `llama-swap` it adds that a restart that needs root can be set in `update.restart.llama-swap.command` while the verb runs unprivileged. A root-owned install root, a missing root and Windows are unchanged. `docs/systems/update.md` describes the check.
- **Checks.** `go build ./...`, `go vet ./internal/update/`, cross-builds of `./internal/update/` and the root package for Linux and Windows, and `go run ./cmd/changelog check`. The refusal itself was not run as root on a Linux node.
