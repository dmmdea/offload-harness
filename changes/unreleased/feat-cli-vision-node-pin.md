### Added - the CLI vision verbs take `--remote` and `--node` to pin a remote call to one fleet node

- **What was missing.** `vqa`, `ocr` and `assess-image` took only `--route local|auto|remote`. A script that sent `vqa --route remote` had no way to say which fleet node ran the call, so it could land on a small NPU node with a 2B model while a GPU node with a 4B vision seat was the one it wanted. The MCP vision tools could narrow the fleet with `remotes`, and the media verbs could name a node; the vision verbs could do neither.
- **What it does.** The three verbs take `--remote <base>` (repeatable) and `--node <id>`, with the meaning and the wording of the media verbs. `--remote` narrows `delegate_remotes` for the call through the rule the MCP vision tools use; a base outside `delegate_remotes` is refused naming it. `--node` is a node id its `/fleet/health` publishes (any case) or a `delegate_remotes` URL, resolved by the helper the media verbs resolve a named node with; a node nobody publishes is refused with the same text, and a node that does not serve the vision task is refused with the lane's own reason. Either flag with no `--route` runs the call on a node (route `remote`), `--node` with `--route auto` never falls back to this machine, and `--route local` with either flag is a contract refusal. A call that passes neither flag is unchanged.
- **Checks.** The built binary, `vqa <image> --question ... --json`: `--route local` with `--node` and with `--remote` each answer a contract refusal, `--remote` with a base outside `delegate_remotes` answers the narrowing refusal, and `--node` with an id nobody publishes answers the media verbs' roster refusal. A pinned call that reaches a node says which one in `meta.node` and `meta.placement`.
