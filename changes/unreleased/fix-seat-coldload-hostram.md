### Fixed - a contract no longer cold-loads the agent seat into a host that cannot take it

- **What was wrong.** A lease release that would warm the agent seat back has asked the host first since the warm-back guard: the seat's footprint (`agent_seat_host_ram_gib`), plus what the live leases have yet to load, must fit, and no lane that declared host RAM may be live. A contract that found the seat cold never asked: its warm-up loaded the seat whatever the host read. Seen on the 3-card reference box: with about 80 GiB already committed by the desktop and its open sessions, one contract's cold load of the vLLM seat took the commit charge to 152.0 of 153.8 GiB. The page file had grown 7 GiB to make room, and the box was 1.8 GiB from refusing allocations.
- **What it does now.** Both contract doors (`runAgentTask` and the MCP `agent_run` door) put the warm-back's rule to a load they would START: the agent seat is not ready and no load is in flight. When the seat does not fit, the run defers as `capacity`, re-placeable, with a reason that starts `host RAM:`, so the delegator places it on another node, and nothing is loaded. A load already in flight (another request started it), a seat that is already loaded, and a model that is not the config's agent seat are not gated. A node that states no `agent_seat_host_ram_gib` keeps the old behaviour: the warm-back's fail-closed default is a chosen figure, not a measurement.
- **Not done.** A request sent straight to llama-swap, outside the harness's doors, still loads the seat ungated.
- **Checks.** On that box with the seat cold, one local-pinned contract through a build with the fix: deferred in 62 ms as `capacity`, `host RAM: the host cannot take the seat's 56.0 GiB ... committed 89.4 of 127.7 GiB physical, 8.0 GiB headroom ...`; the seat stayed unloaded and the commit charge did not move (89.4 to 89.5 GiB). The existing warm-up, admission and coherence tests of both packages pass.
